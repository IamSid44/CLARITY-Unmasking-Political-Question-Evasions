## Key Findings

1. **The public QEvasion release does NOT contain per-annotator columns.** On the HuggingFace dataset `ailsntua/QEvasion`, the columns `annotator1/annotator2/annotator3` are present in the schema but **empty (0 non-null values)**; only `annotator_id` (3 distinct values) is populated. This is a critical, plan-altering fact: HiGrEC's C3/C4 (which need per-annotator or multi-reference labels) cannot draw the dev/test triple-annotations from the public HF file as-is. The multi-annotation must come from the official SemEval scorer/test release (TeleAI and KCLarity both confirm the test set carries 3 labels/instance — KCLarity notes "the test set includes three labels per instance, each provided by a different annotator") or be reconstructed.

2. **TeleAI's win is attributable to specific components, not scale.** Ablation on dev (S2): CoT single-step 9-class 0.490 → +Gate routing 0.465 → +Confidence routing 0.503 → +Refined label definitions 0.520 → +Step-3 few-shot B=10 0.617. The "confusion guide" alone contributes +0.102, larger than boundary examples (+0.024) or gate confidence routing. Same pipeline on weaker backbones still scored 0.556–0.561 (Qwen3-235B, TeleChat3-36B), so the *prompt scaffolding* carries the system.

3. **Both ChulaNLP and TeleAI collapse the multi-reference structure and both fail on the same classes**, but for different reasons: ChulaNLP's encoder *never surfaced Partial/half-answer in top-5* (Acc@5=0.00 for that class), so the LLM could never pick it; TeleAI defaults to "General" in the Dodging–General–Deflection triangle (77.7% of its errors) and to "Implicit" under hedging. Neither exploits the scorer's multi-reference semantics — exactly HiGrEC's G4.

4. **RooseBERT is real and available**, at the HuggingFace collection `MARIANNE-INRIA/roosebert` (Dore, Cabrio, Villata, arXiv:2508.03250; also `deborahdore/RooseBERT` on GitHub), with cont/scr × cased/uncased variants; ChulaNLP's "RooseBERT-base-cased-cont" is the continued-pretraining cased base variant. RooseBERT was pretrained on an 11 GB English political-debate corpus (`MARIANNE-INRIA/PoliticalDebatesCorpus-EN`, 1946–2025). Note ChulaNLP found it *underperformed* truncated DeBERTa-large.

5. **Blackwell (sm_120) is now well-supported for the main stacks as of 2026**, but with real caveats: use CUDA 12.8+ and PyTorch ≥2.7 (cu128); FlashAttention-4 will NOT run on consumer/workstation Blackwell (sm_120 lacks the TMEM subsystem — only sm_100/sm_103 B200/B300 get FA4); use FA2 (Triton) or FlashInfer instead; vLLM works with `VLLM_FLASH_ATTN_VERSION=2`.

6. **Free API tiers sufficient for a re-annotation campaign of a few hundred items exist**: Google AI Studio / Gemini, Groq, OpenRouter free models, Mistral free tier, Cerebras. These plus local open-weight models give ≥3 distinct model families for an LLM "annotator panel."

## Details

### A. ChulaNLP deep dive — reconstructing the pipeline

**Confirmed architecture (from the paper + task context).** Input construction: concatenate x = [q ; a] where q is the LLM-decomposed sub-question and a is the full original answer. Feed to an encoder (DeBERTa-base/large, RooseBERT-base-cased-cont, BigBird-RoBERTa-base) truncated to L (512 for BERT-family, 4096 for BigBird), fine-tuned with a linear classification head over C=9 evasion classes with cross-entropy. From the best encoder M* (truncated DeBERTa-large), compute p* = softmax(logits), sort descending, and extract top-k label sets L_k = TopK(p*,k) for k∈{3,5}. These, plus the full set C, become **constrained label spaces** for LLMs G∈{DeepSeek-V3.2-Exp, Kimi-K2 (kimi-k2-0905-preview)}. The LLM predicts ĉ2 = G(x, L_k), the Subtask-2 output; Subtask 1 is derived by a taxonomy map h: C→Z (Explicit→Clear Reply; Declining/Claims-ignorance/Clarification→Clear Non-Reply; the remaining five→Ambivalent).

**Preprocessing strategies:** "Drop" (keep only QA pairs <512 tokens, following Thomas et al. 2024 stability filtering), "Truncate" (train on full set, truncate >512), "Allow" (BigBird up to 4096). Best config was DeBERTa-large + Truncate.

**Hyperparameters (confirmed):** DeBERTa-base, DeBERTa-large, RooseBERT-base-cased-cont, BigBird-RoBERTa-base; 5 epochs (10-epoch extension for DeBERTa-base and RooseBERT); per-step batch 2 (BigBird 1); grad-accum 8 (BigBird 16); LR 1e-5; warmup ratio 0.1; max-grad-norm 1; model selection by dev macro-F1. Timings on Colab L4: DeBERTa-large truncate 1:24:43; BigBird 3:48:29.

**Key results:** Official test macro-F1 0.61 (S2, 2nd) / 0.82 (S1, 7th); beat the organizer fine-tuned-LLM baseline (0.57/0.82) on S2, tie on S1. Dev best encoder DeBERTa-large truncate: Acc@3 0.77, Acc@5 0.97. LLM-alone dev: DeepSeek zero/few 0.39/0.44; Kimi-K2 0.44/0.45. Hybrid Top-5 Kimi-K2 few-shot 0.52 (dev). Per-class dev F1: Clarification 1.00, Explicit 0.63, Declining 0.62, Claims-ignorance 0.53, Dodging 0.52, General 0.33, Partial/half 0.33, Implicit 0.26, Deflection 0.22.

**The escape problem (verified in paper text):** the LLM sometimes predicted labels ABSENT from the top-5 constraint set — 2 successful, 7 failed instances (Declining, Explicit, Partial/half). The encoder never surfaced Partial/half-answer in its top-5 at all (Acc@5=0.00 for that class), which structurally caps recall for that class.

Therefore I CANNOT verify the exact prompt strings, the output-parsing/fallback logic for out-of-top-k escapes, the API SDK/base URLs, temperature/seed, or the literal 9→3 mapping dictionary at code level. The identity moswisarut=ChulaNLP is confirmed (TeleAI's paper states "ChulaNLP appears as moswisarut on the Codabench leaderboard"). **Action for the user: open the PDF (aclanthology.org/2026.semeval-1.236.pdf) footnote 1 and the SupplementaryMaterial.zip directly, and try `api.github.com/users/moswisarut/repos`.** Based on the reported behavior (7 failed escapes), the code almost certainly does simple string-matching of the LLM's returned label against the allowed set with no robust fallback; a re-implementation should add fuzzy/regex matching and a default-to-encoder-top-1 fallback to eliminate those failures.

### B. ChulaNLP vs TeleAI — head-to-head

| Dimension | ChulaNLP (2nd S2, 0.61) | TeleAI (1st both, 0.68/0.89) |
|---|---|---|
| Fundamental strategy | Discriminative candidate-narrowing → generative pick | Staged generative routing with confidence gate |
| Where label space is reduced | Encoder top-k probability mass (soft, data-driven) | Hard semantic partition on Non-Reply (Gate), then 6-way subdivision |
| Supervision | Fine-tuned encoder on 3,364 labelled items | Zero training; all prompt engineering + confusion-matrix-mined exemplars |
| Backbone | DeBERTa-large + DeepSeek-V3.2/Kimi-K2 | DeepSeek-V3 API, temp 0.0, 1.94 calls/sample |
| Cost | ~1.5 h encoder training on L4 + 1 LLM call/sample | No training; ~2.25M input tokens/308 dev samples |
| S1 derivation | Taxonomy map h from S2 | Deterministic map from S2 |
| Error profile | Encoder caps recall (Partial/half never in top-5) | Defaults to General in evasion triangle; Implicit under hedging |

**Why TeleAI's 0.68 beat 0.61 (attributed to components):** TeleAI's advantage is *not* the backbone (its Qwen2.5-7B version scored only 0.288) but the reasoning scaffold. The mined **confusion guide (+0.102)** directly targets the Dodging–General–Deflection–Implicit boundaries where the dataset's disagreement concentrates (General↔Implicit 12.0%, Explicit↔General 10.7%, Dodging↔General 9.1% of dev). ChulaNLP's encoder-first design instead throws away the rare classes before the LLM ever sees them: since Acc@5 for Partial/half-answer was 0.00, no downstream reasoning could recover it. TeleAI keeps all 9 classes reachable and spends its capacity on boundary disambiguation. Both, however, predict a *single consensus label* and ignore the multi-reference scorer — leaving HiGrEC's G4 gain untouched by both.

**Reproducibility/extensibility for a 50 GB / no-budget student:** ChulaNLP's design is far more reproducible locally — the encoder half is fully free and local; only the LLM half needs an API, and that can be swapped for a free-tier or local open-weight model. TeleAI's design needs ~2.25M input tokens/308 samples per run (×1.94 calls), which is heavy but still within free daily tiers if throttled. HiGrEC should adopt ChulaNLP's *local encoder* efficiency reference and TeleAI's *keep-all-classes* philosophy.

### C. Full HiGrEC implementation plan

**C.0 Data acquisition.** Primary: `load_dataset("ailsntua/QEvasion")` (train 3,448; test 308; license CC-BY-NC-ND-4.0). Fields include title, date, president, url, interview_question, interview_answer, gpt3.5_summary, gpt3.5_prediction, question (the sub-question), clarity_label, evasion_label, annotator_id, annotator1/2/3 (EMPTY in public file), inaudible, multiple_questions, affirmative_questions. Also pull the SemEval-2026 Task 6 Codabench release and the organizers' scorer (the multi-reference test labels live there; the Findings-EMNLP-2024 paper Thomas et al. is at aclanthology.org/2024.findings-emnlp.300, arXiv:2409.13879). **Reconstructing annotator identity:** the training split's single label + `annotator_id` gives per-annotator marginals (random assignment ⇒ marginal differences are annotator effects). The 58 doubly-annotated training pairs (116 rows, of which ChulaNLP kept 32 agreeing) and the 308 triply-annotated test items are the only multi-reference data — small, so C3/C4 estimation capacity is genuinely limited.

**C.1 The attribute code — proposed 9×5 table.** Five attributes: coverage (full/partial/none), engagement (on-target/pivots/ignores), form (stated/implied), marker (present/absent), incompleteness (none/missing-components/missing-specificity).

| Leaf | coverage | engagement | form | marker | incompleteness |
|---|---|---|---|---|---|
| Explicit | full | on-target | stated | absent | none |
| Implicit | full | on-target | implied | absent | none |
| Partial/half-answer | partial | on-target | stated | absent | missing-components |
| General | partial | on-target | stated | absent | missing-specificity |
| Dodging | none | pivots | stated | absent | missing-components |
| Deflection | none | pivots | implied | absent | missing-components |
| Declining to answer | none | ignores | stated | present | none |
| Claims ignorance | none | ignores | stated | present | missing-components |
| Clarification | none | ignores | stated | present | missing-specificity |

All nine codes are unique (verify with a set membership check). Note the design tension: Dodging vs Deflection differ only on `form` (stated vs implied); Declining/Claims-ignorance/Clarification differ only on `incompleteness`. This is deliberate — it forces the model to place probability mass on shared attribute values that rare leaves inherit from common ones.

**Architecture and objective.** Shared encoder/LLM representation → 5 attribute heads. Factorized leaf posterior P(leaf) ∝ Π_a P(attr_a = code_a(leaf)), renormalized over the 9 valid codes; coarse label derived from leaf. **Two candidate objectives:** (i) sum of 5 attribute cross-entropies (each head trained on the deterministic attribute value); (ii) marginal likelihood of the leaf under the factorization (a single CE on the renormalized 9-way posterior). **(ii) is the correct primary objective** because it optimizes the actual leaf metric and lets the renormalization do the work; (i) can be an auxiliary/multi-task term. Report both.

**The crux objection (does a deterministic reparameterization add anything?).** Because attributes are a deterministic function of the leaf, a *softmax over 9 leaves* and a *factorized code* have identical expressive capacity in the infinite-data limit — the code is a reparameterization. It can only help under specific conditions supported by the label-embedding / attribute-based / semantic-output-code literature (Akata, Perronnin, Harchaoui & Schmid, "Label-Embedding for Attribute-Based Classification," CVPR 2013 / TPAMI 2016; Palatucci et al., "Zero-Shot Learning with Semantic Output Codes"; hierarchical softmax): namely when (a) classes are **long-tailed** (rare leaves borrow statistical strength through attribute values shared with frequent leaves — e.g. Partial/half-answer's `partial`+`on-target` are seen thousands of times via General), (b) supervision is **limited** (exactly this dataset), and (c) attributes are **more balanced** than leaves. So HiGrEC's honest claim is: *the code is not more expressive, but it re-allocates the sample-efficiency budget toward rare leaves.* The ablation "code vs flat on rare leaves" is the decisive test; commit in advance to the prediction that gains concentrate on the ≤3% classes (Partial/half, Clarification, Claims-ignorance) and are ~zero on Explicit/Dodging.

**C.2 The re-annotation study — AND the dataset-only shortcut (flag prominently).** The proposal's re-annotation campaign validates whether agreement rises under a coverage-derived coarse cut. **But the single most valuable finding of this research: the core C2 test needs NO new annotation.** Since the coverage attribute is a deterministic function of the existing leaf label, you can:
1. Take the 308 test items, each with 3 independent per-annotator leaf labels.
2. Map each annotator's leaf label under (a) the official 3-way clarity partition and (b) the coverage-derived 3-way partition (full→Clear Reply, partial→Ambivalent, none→Clear Non-Reply, using the C1 table).
3. Compute Krippendorff's alpha (nominal) over the 3 annotators under partition (a) vs (b), plus Fleiss' kappa for comparability.
4. Pre-register the prediction: alpha(coverage cut) > alpha(official cut), with a paired bootstrap over items for significance.

This is *entirely computable from existing data*. Its limitation: it tests whether *relabelling the existing 9-way judgments under a different collapse* raises agreement — it does NOT test whether annotators asked *directly* about coverage would agree more (that still needs the campaign). State this explicitly. The dataset creators report the neighbourhood where annotators disagree most crosses the coarse boundary, so this test is well-motivated. Commit to reporting a negative result if alpha does not rise. (Context: QEvasion's published agreement is Fleiss κ=0.64 for the 3-way clarity task and κ=0.48 for the 9-way evasion task, and only 40.6% of dev samples have unanimous 3-annotator agreement — so there is real headroom to detect a partition effect.)

For the full campaign (venue upgrade): re-annotate a few hundred items with 4–5 annotators each labelling every item, collecting leaf label + independently-assigned attribute code + annotator ID, reusing the original protocol including its counterfactual-injection attention check.

**C.3 The annotator model.** Model observed label ỹ as latent leaf y passed through annotator-specific confusion. Two parameterizations:
- **Marginal-bias vector** b_a∈R^9 added to shared logits: cheap, identifiable from singly-labelled data with random assignment (differences in annotators' label marginals are annotator effects). Recover clean posterior by dropping b_a at inference.
- **Low-rank confusion** A_a = I + U_a V_a^T with a trace/Frobenius regularizer pulling toward identity (Tanno et al. 2019 regularized confusion; crowd-layer of Rodrigues & Pereira 2018, AAAI, doi:10.1609/AAAI.V32I1.11506 — the CrowdLayer applies a learnable per-annotator confusion layer after the classifier and trains end-to-end by backprop; Dawid–Skene 1979 lineage). Full per-annotator matrices are unidentifiable from singly-labelled data — the marginal-bias model is what is actually estimable from the training split.

The 308 triple-annotated test items permit a single **global** confusion matrix estimate (not per-annotator); the 58 (32 usable) doubly-annotated train pairs are too few for per-annotator matrices. **Report this limit honestly**: with ~3 labels × 308 items you can estimate a 9×9 global confusion but per-annotator structure is out of reach; use the constrained marginal-bias model as primary. For the CrowdLayer variants (CL-VW per-class weights, CL-VWB adds bias, CL-MW full matrix), only CL-VW/CL-VWB are realistic here.

**C.4 The decision rule — derived from the scorer.** Scorer semantics (verified from TeleAI Appendix A.1): a prediction p is a TP for class c if p=c AND c∈G (the reference set); a gold class in G incurs an FN only if p∉G entirely (no per-unpredicted-member penalty). So the per-example contribution of predicting class c is: TP if c∈G, FP if c∉G; and the whole set G triggers exactly one FN-type penalty iff p∉G. **Therefore the quantity that matters is q(c|x)=P(c∈G|x), the probability c appears somewhere in the annotator set — NOT the consensus posterior.** Because macro-F1 is non-decomposable across examples, select by a plug-in thresholded rule ŷ=argmax_c λ_c·q(c|x) with per-class λ_c fitted on held-out data (Lipton, Elkan & Narayanaswamy, "Thresholding Classifiers to Maximize F1," arXiv:1402.1892; Koyejo, Natarajan, Ravikumar & Dhillon, "Consistent Binary/Multilabel Classification," NIPS 2014/2015; Narasimhan, Vaish & Agarwal, "On the Statistical Consistency of Plug-in Classifiers for Non-decomposable Performance Measures," NIPS 2014; Ye et al. 2012).

Estimator for q: under conditional independence of the 3 annotators given the latent leaf, q(c|x) = 1 − Π_a (1 − P(annotator a labels c | x)), where each per-annotator probability comes from pushing the latent posterior through the annotator model of C3. Threshold-tuning algorithm: coordinate ascent over per-class λ_c maximizing macro-F1 on held-out data (each 1-D search is over the finite set of distinct q-values, O(N) per class; the plug-in for non-linear macro-F1 is consistent per Narasimhan et al.). **Overfitting risk is severe** with 308 dev items and single-digit rare-class support — use nested/cross-fitted CV (tune λ on inner folds, evaluate on outer), regularize thresholds toward the class base rate, and report the gap between in-fold and out-fold macro-F1. Also compare against a fixed-model + majority-vote-gold + standard-threshold control to separate decision-theoretic gain from modelling gain.

**C.5 Coverage/span module.** Because each sub-question is paired with the full original answer, this is **span selection with a NONE option** (SQuAD 2.0-style answerability). Concrete options, ranked: (1) sentence-level relevance classifier over answer sentences given the sub-question (cheapest, robust); (2) extractive QA span head with no-answer logit; (3) LLM-distilled span labels. **Free supervision:** distil span/relevance judgments from a strong open model (or free-tier Gemini), use self-consistency across ≥2 prompts and agreement-filtering to keep only high-confidence spans. **Transfer resources (verified available):** Circa (Louis, Roth & Radlinski, "'I'd rather just go to bed': Understanding Indirect Answers," EMNLP 2020, aclanthology.org/2020.emnlp-main.601; repo `google-research-datasets/circa`, HF `circa`, CC-BY-4.0/SA) — **34,268 (polar-question, indirect-answer) pairs from 3,431 unique questions with up to 10 answers each, each pair marked by five annotators, gold = majority judgement requiring at least three annotators to agree**; its interpretation labels (Yes / Probably-yes / Yes-with-conditions / No / Probably-no / Middle / can't-interpret) map directly onto HiGrEC's coverage dimension. Also SQuAD 2.0 (answerability), BoolQ, IndirectQA (Müller & Plank 2024), and SWDA-IA/Friends-QIA for indirect-answer transfer. Ablation: a shuffle control that destroys question–answer correspondence must collapse span-module accuracy.

**Baselines, protocol, ablations.** Baselines: (i) flat 9-way softmax over the SAME backbone as the reference baseline (frozen, gated against); (ii) parameter-matched capacity control; (iii) for C4, majority-vote gold with standard thresholding. Protocol: ≥5 seeds (mean±std); bootstrap CIs + per-class support beside every per-class F1; **cross-validation on the TRAINING split as primary** (dev leaves rarest classes single-digit); paired bootstrap significance; distribution shift handled by importance weighting. **Importance-weight formula:** with known label-shift (train→dev proportions: Explicit 30.5→25.9, Dodging 20.5→18.7, Implicit 14.2→18.9, General 11.2→18.6, Deflection 11.1→8.1, Declining 4.2→3.6, Claims-ignorance 3.5→2.9, Clarification 2.7→1.3, Partial/half 2.3→2.0), weight each training example of class c by w_c = P_dev(c)/P_train(c) (e.g. Implicit 18.9/14.2≈1.33, Deflection 8.1/11.1≈0.73), a standard label-shift correction; renormalize so Σ w_c n_c = N. Ablations: code-vs-flat on rare leaves; span shuffle control; decision rule on a fixed model; confusion sub-matrix over the failing neighbourhood before/after C5; coverage- and engagement-factor accuracy separately; accuracy stratified by annotator consensus (unanimous / 2-way / 3-way — dev has 40.6% unanimous, 48.7% two-label, 10.7% three-label). ### D. Annotators — LLM substitutes and dataset-only alternatives

**Is LLM annotation defensible?** The 2024–2026 literature is clear and cuts both ways. Gilardi, Alizadeh & Kubli (2023), PNAS 120(30):e2305016120 (n=6,183 tweets/news), found that **"the zero-shot accuracy of ChatGPT exceeds that of crowd workers by about 25 percentage points on average, while ChatGPT's intercoder agreement exceeds that of both crowd-workers and trained annotators for all tasks," at <$0.003 per annotation (~30× cheaper than MTurk)**. But the consensus for *this* use-case is that **LLMs systematically compress/underestimate human disagreement** ("Can LLMs Capture Human Annotator Disagreements?"; "LLMs Capture Emotion Labels, Not Emotion Uncertainty"; Pavlovic & Poesio 2024; the perspectivism literature — persona variables explain only a small fraction of annotator variance per Hu & Collier 2024). Since HiGrEC *needs the disagreement*, not consensus, this is the central risk. **Recommendation:** LLM annotators are defensible **only for the attribute decomposition (C1)** — an easier, more objective sub-judgment — and **not for the leaf label or for manufacturing the disagreement structure** of C3/C4. Preempt reviewers by (a) validating every LLM annotation against the 308 human triple-annotations, reporting human–LLM agreement (Krippendorff's alpha), (b) using LLMs only to assign the attribute code given the (human) leaf label, and (c) never claiming LLM disagreement is a proxy for human label variation.

**Free LLM re-annotation protocol.** Use **distinct model families as distinct "annotators"** (Gemini 2.5 Flash, a Llama/Qwen on Groq, a local Mistral/Qwen open-weight, DeepSeek free tier) rather than temperature-sampling one model — cross-family diversity better approximates independent annotators and avoids one model's systematic bias dominating (temperature sampling from one model produces correlated, not independent, errors). 4–5 model-annotators. Prompt each for the attribute code **independently of the leaf** (ask for coverage/engagement/form/marker/incompleteness separately, not "which of the 9"). Inject the original protocol's counterfactual/attention-check items. Compute agreement with **Krippendorff's alpha** (preferred over Fleiss' kappa here because it handles the incomplete/variable-rater design and any missing judgments, and generalizes across the 3-way collapses). Run the C2 test as a pre-registered paired comparison: alpha(coverage cut) vs alpha(official cut).

**Dataset-only alternative (the key result, restated).** As in C.2: the entire C2 agreement test is computable from the existing 308 triple-annotated items by collapsing each annotator's leaf label under the two 3-way partitions and comparing alpha — no annotation, no compute, no API. This should be run first and reported prominently; it also de-risks the whole paper if the campaign fails.

**Simulated/bootstrapped annotator sets for C4.** Use the per-annotator marginals from the training split (via `annotator_id`) to simulate plausible reference sets G for threshold tuning: sample latent leaf from the model posterior, corrupt through each annotator's estimated confusion/bias, take the union as a synthetic G. This expands the tiny 308-item multi-reference set for more stable λ_c estimation (report it as data augmentation, validate on real triple-annotations).

### E. Compute & model recommendations (~50 GB Blackwell, free)

**Blackwell software environment (known-good spec).** OS Linux (or WSL2 ≥2.7 on Windows); CUDA 12.8+ (13.x also works); **PyTorch ≥2.7 stable cu128 wheels** (Blackwell/sm_120 officially supported since 2.7.0, April 2025; current stable line 2.10 with cu126/cu128/cu130 builds). transformers ≥4.48, peft ≥0.14, bitsandbytes ≥0.45 (Blackwell support in the 0.45 line), accelerate ≥1.3. **Pitfalls:** FlashAttention-4 does NOT run on sm_120 (silicon-level TMEM gap; only B200/B300 sm_100/sm_103 — RTX 5090/RTX PRO 6000 report cc 12.0 and get FA2 only) — use FA2 (Triton) or the FlashInfer backend; set `VLLM_FLASH_ATTN_VERSION=2`; some builds still need `TORCH_CUDA_ARCH_LIST="12.0"`. Note sm_121 (GB10) is binary-compatible with sm_120 (build FA targeting 12.0). Unsloth supports Blackwell but pin a recent version. NVFP4/FP8 inference is emerging on sm_120 via FlashInfer but treat as experimental; use bf16 or 4-bit NF4/AWQ for reliability.

**Backbone (QLoRA) VRAM math at seq-len 3,072 (this task needs it: 36.6% of train >512 tokens).** Rule of thumb (2026 sizing tables): QLoRA 4-bit base ≈ params×0.5 bytes + adapters+grads+optimizer (~2 GB) + activations (~5–8 GB at 3k).
- **Qwen3-8B QLoRA: ~8–10 GB — trivially fits; recommended "moderate size" primary.**
- **Qwen3-14B QLoRA: ~14–16 GB — comfortable; the sweet spot for "gains from mechanism not scale."**
- **Qwen3-14B LoRA bf16: ~35 GB — fits in 50 GB with headroom; use this to avoid quantization confounds in the controlled study.**
- Qwen3-32B QLoRA ~28 GB fits; but avoid — too large for the "moderate size" argument.
- Gemma 3 12B / Phi-4 (14B) QLoRA ~14–20 GB also fit. **Pick Qwen3-14B (LoRA bf16 ~35 GB) as primary** — moderate, fits, no quantization confound.

**Encoder efficiency reference.** DeBERTa-v3-large is strong but 512-capped — the exact limitation that forced ChulaNLP to truncate and drop Partial/half. **Use ModernBERT-large (395M params, Warner et al., arXiv:2412.13663, ACL 2025 = aclanthology.org/2025.acl-long.127; native 8,192-token context, trained on ~2 trillion tokens) as the primary encoder reference** so no answer is truncated (train reaches 2,500 tokens, dev 1,750 — all fit in 8k). ModernBERT processes 8,192-token sequences at ~46,801 tok/s, "processing documents 2.65 to 3 times faster" than prior long-context encoders, and is competitive with DeBERTa-v3 on NLU. It directly tests whether removing truncation recovers the classes ChulaNLP lost. (Caveat: one controlled study, arXiv:2504.08716, finds DeBERTaV3 still edges ModernBERT on pure NLU sample-efficiency when data is held fixed, though it fails on retrieval — so keep DeBERTa-v3-large as a parity control.) Keep RooseBERT-base-cased-cont (`MARIANNE-INRIA/roosebert`) as a domain-pretraining comparison.

**Local LLM annotators at inference in 50 GB (vLLM).** bf16: 7–14B models fit (Qwen2.5-7B/14B, Llama-3.1-8B, Mistral-7B, Gemma-3-12B). 4-bit AWQ/GPTQ: up to ~32B (e.g. Qwen3-32B-AWQ ~18–20 GB) — enabling ≥3 distinct families swapped sequentially. Throughput with vLLM+FlashInfer on Blackwell is ample for a few hundred to few thousand items (community benchmarks report 60–175 tok/s on 30–35B MoE with AWQ/NVFP4). Swap families sequentially (load, annotate all items, unload) to build the annotator panel within one 50 GB budget.

**Free hosted options (verified 2026, for research/publication use).**
- **Google AI Studio / Gemini:** as of Sept 2026 the free tier for Gemini 2.5 Flash is ~10 RPM / 250,000 TPM / ~1,500 RPD, 1M context, no card (Flash-Lite reaches 15 RPM; the 2.5 Pro free tier was heavily restricted/moved behind billing in 2026, ~50–100 RPD when available). Note Google may train on free-tier prompts — fine for public political-interview data.

- **OpenRouter:** 20+ free models, ~50 req/day (1,000 with $10 top-up), up to 1M context.
- **Mistral:** free "Experiment" tier, no card (may use data).
- **Cerebras:** ~5 RPM, ~1M tokens/day free.

For a ~300–500 item panel at 4–5 model-annotators, these daily quotas are sufficient over 1–2 days; local models remove the quota entirely.

## Recommendations

1. **Do the dataset-only C2 alpha test FIRST (week 1).** It's free, needs no annotation, and is the highest-value/lowest-risk result. Threshold that changes the plan: if alpha(coverage cut) − alpha(official cut) is positive and survives paired-bootstrap at p<0.05, C2 is a headline positive; if not, report the committed negative result and pivot emphasis to C1+C4.
2. **Backbone: Qwen3-14B, LoRA in bf16 (~35 GB)** for the controlled study (no quantization confound); fall back to Qwen3-8B QLoRA if concurrent jobs squeeze VRAM below ~40 GB. Encoder reference: **ModernBERT-large (8k)** to fix the truncation loss; keep DeBERTa-v3-large for ChulaNLP parity.
3. **Implement C4 with nested cross-fitted thresholds** and always report the fixed-model + majority-vote control, or reviewers will attribute the gain to overfitting on 308 items.
4. **LLM annotators only for the attribute decomposition, validated against the 308 human triples.** Use ≥3 distinct model families (Gemini Flash + Groq-Llama + local Qwen), never one model at high temperature. Do not claim LLM disagreement = human label variation.
5. **Course deliverable scope:** C1 (factorized code + rare-class ablation) + C2 (dataset-only) + C4 (decision rule + control) + flat/parameter-matched baselines + ≥5 seeds + bootstrap. **Venue upgrade:** full 4–5 annotator campaign (releases the multi-annotation resource, enables the direct C2 test and per-annotator C3), extractive-QA span head, backbone sweep, importance-weighted shift analysis.
6. **Environment:** pin PyTorch cu128 ≥2.7, bitsandbytes ≥0.45, transformers ≥4.48, `VLLM_FLASH_ATTN_VERSION=2`, FlashInfer backend; do NOT attempt FlashAttention-4 on Blackwell consumer/workstation cards.

## Caveats
- **ChulaNLP code internals are unverified** — the repository and supplementary ZIP were not retrievable through my tools; exact prompts, parsing/fallback, seeds, and the literal 9→3 dictionary must be read from the PDF/supplement directly. The pipeline reconstruction above is from the paper's reported design and results, which are reliable, but code-level strings are not confirmed.
- **The public HF QEvasion file has empty annotator1/2/3 columns**; the multi-reference labels needed for C3/C4 must come from the official scorer/test release. Confirm this before building C3/C4.
- **C3 is capacity-limited**: only a global confusion matrix (from 308 triples) and marginal-bias vectors (from training `annotator_id`) are estimable; per-annotator confusion matrices are not identifiable from this data. State this as a limitation, not a bug.
- **The attribute code is a reparameterization, not a capacity increase**; its value is purely sample-efficiency on rare classes and must be demonstrated empirically (code-vs-flat ablation), not asserted.
- **Free API tiers and Blackwell software support change frequently**; verify current quotas and wheel availability at setup time. Groq's exact free RPD and Gemini's exact free RPM vary between published sources.
- Some 2026 model/version names surfaced in search (e.g. "DeepSeek-V4," "Gemini 3.5 Flash," "Kimi K3") could not be independently corroborated as of writing and are not relied upon in the recommendations.
